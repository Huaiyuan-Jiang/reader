# 发布安全检查 · 2026-10-13

本文记录 v1.0.0 的初次隐私检查。v1.0.1 的异常输入、压力修复和验证记录见 [本轮测试说明](VALIDATION_2026-10-13.md)。新增教程截图均使用合成书籍与空 AI 配置。

## 范围与结论

发布源是经清理的公开版本及其单提交历史；后续发布修补也纳入检查。检查范围包含源码、AI 系统提示词、界面文字、注释、测试与演示数据、配置示例、文档、提交身份、源码 ZIP 和最终 Windows EXE。

在本轮检查范围内，未发现开发者真实 API Key、登录令牌、私人邮箱、机器用户名、个人介绍、个人书籍、笔记、阅读记录或登录目录进入发行内容。所有命中的示例邮箱、示例路径和测试 Key 已核对为测试或文档占位内容。历史中只使用 GitHub 的 noreply 邮箱。

GitHub 账号名称、提交中的 GitHub 匿名邮箱及 Release 发布者仍能关联到发布账号。该项目不能提供账号身份匿名性；本轮检查也不能保证第三方以前保存的旧内容已被删除。

## 方法

- Gitleaks v8.30.1 检查 Git 历史与待发布源码，扫描器下载包经官方 SHA256 清单核对。
- 检查源码中的外部服务、文件路径、邮箱、凭据读取、错误信息、日志与打包入口；重点复核 AI 提示词和可见文案。
- 从干净源码和独立 Python 环境构建；原始开发目录及其个人数据未用于构建。
- 解开 PyInstaller 归档，检查文件清单、Python 模块、递归代码对象中的调试文件路径及常量，另检查二进制中的开发路径。
- 对实际 EXE 执行离线自检，对构建环境执行 pip-audit 已知漏洞扫描。

## 发布修补

- 移除旧 MiMo 本机凭据文件的加载入口，并在打包配置中排除该模块。
- MiMo 错误不再直接展示服务器错误正文，减少意外回显敏感内容。
- 阅读日志不再记录书名、完整结束摘要及旧会话对象；正常阅读数据仍保存在用户自己的本机数据目录。
- 补齐 PDF 渲染必需的 NumPy，固定界面依赖版本，并保存完整构建依赖版本。
- 原生组件查找限制在构建 Python 环境与 Windows 中，防止打包其他软件放在 PATH 上的同名 DLL。
- 源码包使用显式允许清单，不收集凭据、个人配置、阅读数据、截图、缓存或 Git 目录。

## 验证

完整单元与界面测试：245 项，244 项通过，1 项真实账号测试默认跳过。测试使用离屏界面和独立数据目录，不调用真实模型，不开启真实锁屏。

EXE 离线自检覆盖 PDF 打开、NumPy 出图、PDF 子进程出图与退出、EPUB 打开、Windows DPAPI 凭据加密读写、AI / Claude SDK / Windows OCR 导入，以及书架界面。

构建环境 pip-audit 检查未发现已知漏洞。该结果针对 Python 依赖和扫描时可用的漏洞数据库，不等同于所有第三方原生组件均不存在未知漏洞。

## 使用时的数据边界

API Key 由使用者提供，界面保存时使用 Windows DPAPI；发行包不内嵌开发者的 Key。远程 HTTP 接口要求 HTTPS，不跟随重定向；本机接口允许 localhost HTTP。

启用 AI 后，选用的书籍片段、提问、页图或笔记上下文会发送给使用者选择的服务。这是功能所需的数据传输，服务提供方的保存规则由其自身决定。本地 Harness 命令由使用者的本机配置指定，应只连接可信工具。

自检在构建电脑上完成；尚未在独立新电脑、不同 OCR 语言组合或每家真实模型账户上逐一验证。EXE 未做代码签名。
