# reader 修复版测试记录

2026-10-13，v1.0.1。此文记录发布前完成的本地修复与验证。

## 方法

三名独立 Luna 子代理分别模拟新手误操作、异常文件与输入、连续操作和压力使用。发现问题后先保留可复现测试，再修复运行源码，最后由专项测试与完整回归确认。

所有书籍由程序合成，模型与 OCR 使用假响应；界面测试运行在 offscreen，开启 READER_NO_LOCK 并使用独立临时数据目录。未使用个人书籍、阅读记录、真实账号或收费模型，未开启真实锁屏。

## 已修复的问题

- 损坏的 library.json 原先被静默当作空书架，后续加书会覆盖原文件。现在先保存原始备份并在书架显示恢复提示，保留能读取的正常条目。
- 错误容器、路径、位置、书目格式和识别状态字段可能使整个书架报错。现在隔离坏条目，并恢复非法的已知设置。正常 EPUB 实际打开、正文读取的回归通过。
- 重新找文件原先接受 TXT、错误格式或损坏文件。现在验证与原书同格式且能打开，失败时保留原路径。
- 没有正文的 EPUB 原先可以导入。现在给出可读错误并拒绝导入。
- 小测 answer 的小数或 bool 原先被 int() 转成合法选项。现在只接受 JSON 整数 0 至 3；不合格输出仍走原来的重试或跳过流程。
- OCR 缓存中的错误页面、词记录或超大坐标会导致选择文字或启动报错。现在过滤不合规缓存数据；极端整数阅读位置先限制到进度范围，再换算比例。
- 同一本书由多个 OCR worker 并行保存时，固定临时文件和旧内存副本会丢页。现在跨实例串行合并、使用唯一临时文件并原子替换。修复覆盖同一进程的多线程；应用本身仍使用单实例与串行 OCR 队列。
- 阅读结束原先只删除控制对象，独立阅读窗口没有销毁。现在显式删除窗口，清理可重复调用。
- 永久主题 bus 保留已销毁控件的回调，造成残留订阅和内存增长。现在订阅绑定控件生命周期，普通 Python bound method 使用弱引用，遮罩撤销时也退订。
- 书架销毁后，静态零延迟焦点回调仍可能执行。现在单次计时器绑定窗口 QObject context，并在焦点恢复时检查对象有效性。

| 连续阅读会话 | 完整 ReaderApp 清理路径执行 60 轮，包含预热、DeferredDelete 和垃圾回收；screen 与 widget 各销毁 60 次 |

修复前会话泄漏探测在约 398 MiB 时停止，以避免过度消耗机器资源。修复后对象级与订阅级断言通过，内存曲线稳定。耗时受机器负载影响，记录的是测试覆盖与回收证据，不作为所有电脑的速度承诺。

## 教程

新增 Markdown 图文教程与独立 HTML 手册，软件书架增加“新手教程”入口。HTML 内嵌 5 张真实软件界面截图，全部使用合成书籍与空 AI 配置；可离线阅读、放大截图、勾选进度和搜索常见问题。

浏览器中验证了进度勾选、关键词搜索（包含“退出”与“出口”匹配）、问题展开、截图放大/关闭及窄窗口布局。无页面脚本错误。
